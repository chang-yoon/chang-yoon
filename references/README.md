# 모든 지원서에 적용하는 참고자료 검토 가이드

현대자동차·기아·GM·구 현대미포 선배 자료는 해당 회사 지원에만 사용하는 자료가 아닙니다. 모든 기업의 자기소개서를 새로 작성하거나 첨삭할 때, 말투와 경험 전개 방식을 검토하는 공통 참고자료로 활용합니다. 사용자 요청 반영일: 2026-09-21.

## 작성 전에 읽을 자료

| 자료 | 전달받은 결과 | 공통으로 참고할 점 |
| --- | --- | --- |
| [현대자동차](automotive-peer-examples/hyundai-project-management.md) | 최종합격 | 직무를 정의하고 실제 행동·도구·제약과 연결하는 방식 |
| [기아](automotive-peer-examples/kia-advanced-parts.md) | 1차 면접 탈락 | 같은 경험을 지원 직무의 관점으로 재구성하고 판단 근거를 설명하는 방식 |
| [GM](automotive-peer-examples/gm-avd-svi.md) | 전화 면접 합격 후 지원 중단 | 기술 간 연결과 협업을 설명하는 방식 |
| [구 현대미포](shipbuilding-peer-examples/README.md) | 채용연계형 인턴 최종합격 | 작업 부담·책임·일정·분담을 통해 갈등 해결 행동을 구체화하는 방식 |
| [공통 작성법](automotive-peer-examples/writing-playbook.md) | 작성 분석 | 행동 동사, 도구의 목적, 경험과 직무의 연결 기준 |

결과는 사용자에게 전달받은 정보이며 특정 문장이 합격·탈락의 원인이었다는 뜻은 아닙니다. 네 자료를 검토하되 모든 글에 네 가지 방식을 억지로 넣지는 않습니다.

## 실제 작성 순서

1. 현재 공고의 업무·지원요건과 문항·글자 제한을 확인합니다.
2. 위 자료의 말투와 구성 방식을 검토하고 이번 문항에 적합한 방식을 선택합니다.
3. 본인의 확인된 경험 중 소재를 고르고, 문항별로 보여줄 역량과 사건을 구분합니다.
4. 문제와 제약, 판단 이유, 본인의 행동, 확인된 결과가 자연스럽게 연결되도록 씁니다. 모든 문단에 동일한 형식을 강제하지 않습니다.
5. 경험이 직무와 어떻게 연결되는지 설명하되, 회사 소개나 포부가 본인 행동보다 길어지지 않게 합니다.
6. 불필요한 기술 명칭, 반복되는 추상적 표현, 같은 사건의 반복 설명을 줄입니다.
7. 사실·개인 역할·결과·분량을 확인한 뒤 최종 문안을 제공합니다.

## 말투와 세부 정보의 기준

- 담백한 1인칭 문장으로 무엇을 보고, 판단하고, 바꾸었는지 씁니다.
- ‘크게 기여했습니다’, ‘성공적으로 이끌었습니다’만 쓰지 않고 그 근거가 되는 행동을 붙입니다.
- 협업은 단순히 소통했다고 끝내지 않고 누구와 어떤 조건을 확인하고 조율했는지 설명합니다.
- 기술명은 판단이나 직무 역량을 이해하는 데 필요할 때만 씁니다. 별도 요청이나 문항상 요구가 없다면 익형 번호·세부 변수명은 생략합니다. AI 추론 연동, 좌표 보정 등 행동을 설명하는 핵심 표현까지 없애지는 않습니다.
- 수치는 검증 가능한 범위와 규모를 설명할 때만 사용합니다. 숫자가 없다고 성과를 만들지 않습니다.
- 큰 사건만 고르지 않습니다. 실제 작업 방식이나 역할 분담을 개선한 경험도 적합할 수 있습니다.
- 같은 프로젝트를 여러 문항에 쓸 수 있지만 역량·판단·갈등·성장 중 문항이 요구하는 관점을 나눕니다. 같은 문제 해결 과정은 반복하지 않습니다.
- 선배의 문장과 경험을 복사하지 않습니다. 회사별 기술 용어와 조직 정보는 현재 공고와 대조합니다.

## 보관과 향후 활용

본인의 지원 기록은 `applications/`, 선배 자료 분석은 `references/`에 분리합니다. 이 가이드는 앞으로의 작성과 검토에 적용하며 이미 제출한 지원서 본문을 소급 수정하지 않습니다. 저장된 지침을 다시 읽어 활용하는 방식이며 모델 자체의 학습을 의미하지 않습니다.
