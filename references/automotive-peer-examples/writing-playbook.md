# 공통 작성법과 본인 경험 적용

## 가장 배울 점

세 문서에서 반복되는 강점은 성격을 선언한 뒤 설명을 끝내지 않고, 직무에서 필요한 행동과 도구를 붙이는 방식입니다. 특히 같은 자작차 경험을 회사·직무에 따라 일정과 비용, 부품 설계, 시스템 간 연결의 관점으로 다르게 편집합니다.

기본 구조:
직무에서 해야 할 일 → 필요한 역량 → 실제 제약 → 본인의 행동·도구 → 판단 근거 → 확인된 결과 → 직무에서 활용할 부분.

모든 글에 이 순서를 강제하지는 않습니다. 400자 강점 문항은 강점과 짧은 근거를 먼저, 상세활동은 실제 행동과 조건을 자세히 씁니다.

## 말투

| 참고할 특징 | 활용 방법 | 그대로 따라 쓰지 않을 점 |
| --- | --- | --- |
| 행동 동사 중심 | 검토했다, 비교했다, 조정했다, 공유했다, 구현했다처럼 대상과 행동을 연결 | 크게 기여했다, 성공적으로 이끌었다만 반복 |
| 제약을 먼저 명시 | 일정, 예산, 장착 위치, 안전 조건 등 무엇 때문에 판단이 필요했는지 설명 | 힘들었다·촉박했다로 상황을 과장 |
| 도구에 목적을 연결 | 도구로 무엇을 비교하거나 공유했는지 바로 설명 | CATIA·NX·Altair·Notion 등 도구명만 나열 |
| 경험을 직무 언어로 해석 | 설계 변경이 다른 팀 작업에 미치는 영향을 설명 | 모든 문단 끝에 기여하겠다는 포부 반복 |
| 소제목으로 요점 제시 | 필요한 경우 해결한 문제나 강점을 짧게 표시 | 막연한 구호·과도한 영어 표현 |
| 수치로 범위 구체화 | 검증할 수 있는 대상 수, 기간, 비교 조건을 기재 | 근거 없는 개선율·성공률로 성과 부풀리기 |

## 핵심 용어와 사용 조건

| 용어 | 의미·사용 맥락 | 본인 경험에 쓸 수 있는 범위 |
| --- | --- | --- |
| 일정관리·선행 작업·인수인계 | 작업 간 의존관계와 전달 자료 관리 | 실제 일정표·인수인계 자료가 있을 때 |
| 설계 변경·부품 간 간섭 | 변경된 형상이나 배치가 다른 요소와 충돌하는지 검토 | 드론의 장착 위치 검토와 연계 가능. 정식 CAD 간섭검사를 했다고 확대하지 않음 |
| 시스템 통합·연계 | 개별 기능이 전체 목적대로 작동하게 연결 | 드론 AI 추론 결과와 이동·조준·분사 연동 |
| 판단 기준·대안 비교 | 같은 기준으로 여러 안을 검토 | CFD 익형 비교와 MODDE 분석 |
| 안전 기준·동작 제한 조건 | 위험 조건에서 허용되는 행동과 중지 조건 | 군 조교 사로 안전통제, 드론 통신 이상 대응. 산업 규격 인증 경험과 구분 |
| 비용·예비비·외주 가공 | 금액과 가공 범위, 납기 등을 관리 | 본인 경험 미확인. 선배 사례를 옮기지 않음 |
| 하드포인트·타이로드·토·볼조인트 | 조향·현가 기하와 부품 관련 용어 | 선배의 조향 사례 이해용. 본인의 드론 경험을 꾸미는 용도로 사용하지 않음 |
| 검증·해석·시험 | 모델 결과와 실물 결과를 구분 | CFD 수치해석과 드론 실제 시험을 별도로 설명 |

## 본인 경험에 적용한 독자적인 문장 예시

다음은 원문 인용이 아니라, 본인이 확인한 경험을 바탕으로 새로 구성한 예시입니다.

- 드론: 영상의 목표점과 실제 분사 위치가 어긋나자 HW 담당자와 카메라·노즐의 장착 조건을 검토하고, 위치 차이를 반영한 좌표 보정을 공동 구현했습니다.
- AI 활용: AI 비전 모델의 추론 환경을 구성하고, 인식 결과를 드론의 이동·조준·분사 판단에 연동했습니다.
- 데이터 유효성: 결과의 임무 식별정보·순서·시각을 확인해 오래된 데이터를 폐기하고, 통신 이상 시 동작을 제한하는 로직을 공동 구현했습니다.
- CFD: 익형별 유동장과 성능 지표를 비교하고, 해석 조건과 적용 범위를 함께 검토하며 설계안 선정에 참여했습니다.
- 군 조교: 100명이 넘는 후보생 앞에서 동작을 설명하고 시범을 보였으며, 화기 교육에서는 사로 안전통제를 맡았습니다.

## 경험별 사실 경계

- 드론 SW·통합 임무 구현과 AI 추론 환경 구성은 본인 설명에 근거합니다. AI 모델 학습을 직접 주도했다고 바꾸지 않습니다.
- 좌표 보정·통신 이상 대응은 공동 구현입니다. 정밀 세척 90% 성공은 검증된 수치가 아니므로 사용하지 않습니다.
- CFD는 4인 공동 수행입니다. 선배의 자작차 설계·외주비 절감 수치를 가져오지 않습니다.
- 봉사동아리의 실제 직책은 임원입니다. 부회장·회장은 아닙니다.
- 종합설계경진대회 발표를 본인이 했다는 서술은 사용하지 않습니다. 팀 수상 사실과 개인 기여를 분리합니다.
- 프로그래밍 숙련자라는 포장보다 실제 구현 범위와 협업 과정을 설명합니다.

## 다음번 면접 준비에 활용

원문 사례에 좋은 결과가 나왔다고 적혀 있더라도 아래 질문에 답할 수 있는지는 별도입니다.

1. 그 도구와 기준을 고른 이유는 무엇인가?
2. 본인이 한 일과 팀원이 한 일은 어떻게 구분되는가?
3. 변경 전후의 비교 조건과 측정 기준이 동일한가?
4. 설계·해석 결과와 실제 작동 결과는 일치했는가?
5. 남은 문제와 다시 수행한다면 바꿀 부분은 무엇인가?

자료별 결과만으로 합격률, 유리한 문장 길이, 특정 말투의 효과를 통계적으로 추정하지 않습니다.
